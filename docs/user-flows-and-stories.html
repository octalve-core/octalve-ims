User Flows & User Stories

Who uses Octalve IMS, what they do in it, and how those journeys connect end to end — grounded in the actual route config, order/ invoice/ticket status fields, and demo accounts already in this repo.

Engineering docs: PROJECT_WALKTHROUGH.md · auth-system-port-plan.md · Markdown twin of this page: user-flows-and-stories.md

1 · Personas

Every persona starts at the same front door — Authentication — then branches by role.

STORE OWNER

Admin

Runs the whole store: catalog, orders, invoices, warehouses, people, moderation. Home: /

CLIENT

Client

Buys from the store: browses, orders, pays invoices, reviews, raises tickets. Home: /client

SUPPLIER

Supplier

Fulfills from their own catalog: manages products, tracks orders/revenue scoped to themselves. Home: /supplier

RETAILER

Retailer

Exists in the RBAC table and login demo-select for QA; no dedicated portal yet — shares the general dashboard. Home: /

2 · Authentication Flow

Get a visitor into the workspace that matches their role — low friction for demo/QA, real security (bcrypt, CSRF, rate limiting, rotating refresh tokens) for production.

  1. Visitor lands on /login.
  2. Optionally picks a demo role from "Test Accounts To Login With" — pre-fills one of the 4 canonical demo accounts.
  3. Enters email + password, or clicks Continue with Google.
  4. Optionally checks "Keep me signed in" — 1-day refresh token unchecked, 30-day checked.
  5. Server validates, rate-limits by ip:email, issues access + rotating refresh token cookies (httpOnly).
  6. Redirected by role — client → /client, supplier → /supplier, everyone else → /.
  7. Session silently refreshes every ~13 minutes while active; a hard 401 anywhere bounces back to /login.
  8. Logout (any role, sidebar footer): confirmation dialog → cookies cleared server-side → redirect with goodbye toast.

3 · Admin / Store Owner Flows

The Admin sidebar is grouped into My Store (day-to-day operations), Management (catalog/people admin), and My Activity.

3.1 Store Overview /

The landing dashboard: store-wide stats (products, orders, revenue, invoices, warehouses, suppliers, categories — including client/supplier activity, not just the admin's own), a Quick Access grid to every section, and inline Products/Suppliers/Categories lists. "My Activities" is the personal-only equivalent.

3.2 Product management

  1. Admin opens Products, sees stock/status/QR per row.
  2. Create a product — name, SKU, price, category, supplier, opening stock, expiry date.
  3. Import products in bulk (CSV) or export the catalog.
  4. Edit or delete a product (confirmation dialog).
  5. Low-stock / stock-out counts surface on stat cards and drive warehouse allocation decisions.

3.3 Orders

Order status lifecycle:

pendingconfirmedprocessingshippeddelivered cancelled (from any pre-delivered state)

Payment status (tracked independently):

unpaidpartialpaid refunded
  1. Admin reviews incoming orders, confirms → allocates stock across Warehouses (auto-assign or manual pick, capped at on-hand quantity).
  2. Advances status as fulfillment progresses — the client sees the same status live.
  3. Cancels/refunds when needed — reflected in both the order and its linked invoice.

3.4 Invoices

draftsentpaid overduecancelled

Generated from orders; Admin can resend, mark paid, or cancel.

3.5 Warehouses & stock

Admin manages warehouse records and allocates order stock across them (auto-assign or manual, capped per-warehouse). Transfers between warehouses are also supported.

3.6 – 3.8 Tickets, Reviews, People

  • Support Tickets: triage, reassign, reply. Lifecycle: open → in_progress → resolved → closed. Priority: low / medium / high / urgent.
  • Product Reviews: client-submitted, moderated pending → approved or rejected before going public.
  • Supplier Portal / Client Portal (admin view): read/manage each supplier's and client's own activity from the admin side.
  • User Management: create users, assign roles, suspend/delete (confirmation dialog).
  • Activity History: audit trail. Business Insights: analytics beyond dashboard totals. Email Preferences: which notification emails the admin receives.

4 · Client Flows

Nav: Client Portal · Browse Products · My Orders · My Invoices.

  1. Lands on /client — personal snapshot (orders, invoices due, recent activity).
  2. Browse Products — catalog, filter by category/supplier, see stock availability.
  3. Place an order — the system checks real stock availability and blocks over-quantity requests.
  4. Track the order through pending → confirmed → processing → shipped → delivered, live.
  5. Pay an invoice generated from the order — unpaid/partial → paid.
  6. Write a product review once delivered — enters pending moderation.
  7. Raise a support ticket for order/product/invoice issues — same lifecycle Admin sees.
  8. Receives notifications for status changes, due dates, and ticket replies.

5 · Supplier Flows

Nav: Supplier Portal · My Products · View Orders · Related Invoices.

  1. Lands on /supplier — snapshot scoped to their own catalog: products, orders containing their products, pending orders awaiting action, and revenue (paid/due/partial/refund, excluding cancelled).
  2. My Products — manage only the products they supply.
  3. View Orders — any order containing at least one of their products; fulfillment actions typically stay with Admin.
  4. Related Invoices — view-only detail, same /invoices/[id] route Admin/Client use.
  5. Sees a Monthly Revenue trend chart (6 months) and a Pro-tier upsell card (multi-warehouse allocation, AI demand forecasting).
  6. Same support-ticket and notification access as every role.

6.3 Notifications

Bell icon in the topbar, every role. Sources: order status changes, invoice due/overdue, ticket replies, low-stock alerts (admin/supplier). Each is individually dismissible with the same confirmation-dialog pattern used for logout and other destructive actions.

8 · User Stories

Format: As a persona, I want to action, so that benefit. P0 core/day-one · P1 important · P2 nice-to-have.

Authentication

#PriorityStory
US-01P0As a visitor, I want to sign in with email/password, so that I can access my workspace.
US-02P0As a visitor, I want to sign in with Google, so that I don't need a separate password.
US-03P1As a returning user, I want a "Keep me signed in" option, so that I'm not forced to re-login every day on my own device.
US-04P2As a QA tester, I want a role-based demo-account select on login, so that I can exercise every persona without memorizing credentials.
US-05P0As any logged-in user, I want a confirmation prompt before logging out, so that I don't lose my session by an accidental click.
US-06P1As a new user, I want to self-register an account, so that I can start using the store without waiting on an admin invite.

Store Owner (Admin) — Catalog & Operations

#PriorityStory
US-07P0As a Store Owner, I want a single dashboard with store-wide totals, so that I can gauge business health at a glance.
US-08P0As a Store Owner, I want to create/edit/delete products with category, supplier, price, and stock, so that my catalog stays accurate.
US-09P1As a Store Owner, I want to bulk-import/export products via CSV, so that I can onboard or migrate a large catalog quickly.
US-10P0As a Store Owner, I want to see low-stock and stock-out counts on the dashboard, so that I can reorder before I run out.
US-11P0As a Store Owner, I want to review and confirm incoming orders, so that fulfillment only starts on orders I've vetted.
US-12P0As a Store Owner, I want to allocate order stock across specific warehouses, so that fulfillment reflects real warehouse availability.
US-13P0As a Store Owner, I want to advance an order through its full lifecycle, so that the client always sees accurate status.
US-14P1As a Store Owner, I want to cancel or refund an order, so that I can handle exceptions without a false "delivered" state.
US-15P0As a Store Owner, I want invoices generated from orders and trackable through their lifecycle, so that I know what revenue is outstanding.
US-16P1As a Store Owner, I want to manage warehouses and transfer stock between them, so that I can rebalance inventory as demand shifts.
US-17P0As a Store Owner, I want a badge-counted sidebar, so that I never lose track of what's pending.

Store Owner (Admin) — People & Moderation

#PriorityStory
US-18P0As a Store Owner, I want to create users and assign roles, so that I control who can do what.
US-19P1As a Store Owner, I want to suspend or delete a user account (with confirmation), so that I can revoke access without accidental data loss.
US-20P1As a Store Owner, I want a read view into each client's and supplier's own portal activity, so that I can support them without asking them to screen-share.
US-21P0As a Store Owner, I want to triage, reassign, and reply to support tickets by priority, so that urgent issues get handled first.
US-22P1As a Store Owner, I want to approve or reject client-submitted product reviews, so that spam never reaches the storefront.
US-23P2As a Store Owner, I want an activity-history audit trail, so that I can answer "who changed this and when."
US-24P1As a Store Owner, I want business-insights analytics beyond headline numbers, so that I can spot trends, not just totals.
US-25P2As a Store Owner, I want to control which notification emails I receive, so that I'm not flooded with alerts I don't need.

Client

#PriorityStory
US-26P0As a Client, I want to browse the catalog with category/supplier filters, so that I can find what I need quickly.
US-27P0As a Client, I want an order blocked if stock isn't actually available, so that I never order something I can't receive.
US-28P0As a Client, I want to track my order's status in real time, so that I know when to expect delivery.
US-29P0As a Client, I want to view and pay my invoices, so that I can settle what I owe without a manual back-and-forth.
US-30P1As a Client, I want to write a review after delivery, so that I can share feedback on the product.
US-31P1As a Client, I want to raise a support ticket tied to my order/invoice, so that I have a documented, trackable way to resolve issues.
US-32P1As a Client, I want notifications when my order/invoice changes, so that I don't have to keep checking manually.

Supplier

#PriorityStory
US-33P0As a Supplier, I want a dashboard scoped to only my own data, so that I never see or worry about other suppliers' data.
US-34P0As a Supplier, I want to manage only the products I supply, so that I control my own catalog.
US-35P0As a Supplier, I want to see every order containing at least one of my products, so that I know what I need to fulfill.
US-36P1As a Supplier, I want view-only access to invoices tied to my orders, so that I can confirm billing without editing rights I shouldn't have.
US-37P1As a Supplier, I want a revenue trend chart, so that I can track my own earnings over time.
US-38P2As a Supplier, I want to see what Pro-tier features unlock, so that I can decide if upgrading is worth it.

Cross-cutting

#PriorityStory
US-39P0As any user, I want a confirmation dialog before any destructive action, so that I can't lose data with one misclick.
US-40P1As any user, I want to dismiss a confirmation dialog by clicking outside it, so that backing out doesn't require hunting for Cancel.
US-41P1As any user, I want individually dismissible notifications, so that I can clear what I've seen without losing what's new.
US-42P2As any user, I want light/dark mode, so that the app is comfortable in my environment.
US-43P1As any user, I want a working global search in the topbar, so that I can jump to any page without hunting through the sidebar.
