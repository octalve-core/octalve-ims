# Scan 2026-10-21 — documentation accuracy

Method: every documentation file read against the code with grep and ls. Documents audited: `README.md`, `CLAUDE.md`, `DEPLOYMENT.md`, `SECURITY.md`, `.env.example`, everything under `docs/` as it stood before this scan, `out/` (spot check), the header comments of `tier-manifest.json`. The new `docs/adr`, `docs/issues`, `docs/tasks`, `docs/development-history` and `tests/walkthrough` were not audited. Nothing was run. Findings come from a delegated reviewer (model output); **re-verified** means re-read by the main session on 2026-10-21. Register rows: `README.md` (type "Docs drift"). Line numbers are those at the time of the scan.

## A. The items that omit or contradict dangerous behaviour

1. **Self-registration makes every new user an admin** (re-verified in code). `docs/user-flows-and-stories.md:63-65` says only "defaults to the user/admin-tier role Milestone-0 policy"; `README.md:74-80` does not mention it.
2. **"Most routes require a valid session; webhooks use provider signatures" is false** (`README.md:462`, `:165`): `POST /api/notifications` has no auth (re-verified), `/api/shipping/webhook` has no signature check (re-verified), `/api/health`, `/api/openapi`, `/api/performance`, `/api/system-metrics` are public. Needs an "Unauthenticated endpoints" table.
3. **`INTERNAL_API_KEY` unset means `Bearer undefined` authorizes the caller** (re-verified). `README.md:365` and `.env.example:111` present it as optional with no warning; `DEPLOYMENT.md:75-82` omits it from the env table.
4. **Wipe scripts and tests run against whatever `DATABASE_URL` points at.** `README.md:301-308` and `:634-635` recommend `script:reset-demo-db` and `script:seed-full-demo` without saying they delete everything; the scripts only print a warning (`scripts/reset-demo-db.ts:60`, `prisma/seed.ts:21`); `npm run test` (`README.md:292`, `CLAUDE.md:16`) runs 21 database-backed test files and `tenant-prisma.test.ts` writes rows; `docs/local-dev-setup.md:7-14` describes a local `roji` database, which contradicts the real `.env` (two `DATABASE_URL` lines, both Neon, which `DEPLOYMENT.md:32-37` says is staging).
5. **Auth description is stale.** `README.md:139` "JWT cookie `session_id`": reality is `access_token` (15 min, path `/`) plus `refresh_token` (path `/api/auth/refresh`) (`lib/auth/cookies.ts:22-39`, `jwt.ts:40-47`). `README.md:319-323` says unchecked "Keep me signed in" is a 1-day refresh and checked is 30 days, but the refresh route re-issues `REFRESH_DAYS.default` (7 days) on every rotation (`refresh/route.ts:99-115`) and the client refreshes every 13 minutes (`hooks/use-auth-refresh.ts:21`), so "1 day" never holds past the first refresh. Same stale claim at `MANUAL_TEST_FIXTURES.md:249`, `PROJECT_WALKTHROUGH.md:284` and `:377`, `CLAUDE.md:1395` (`SESSION_JWT_EXPIRES` and `sessionCookieOptions` do not exist). The login API default `rememberMe=true` (`login/route.ts:65-68`) is undocumented.
6. **Rate-limiting claims overstate reality.** `user-flows-and-stories.md:41,51-52` ("rate-limits by `<ip>:<email>`") and `auth-system-port-plan.md:34,101,137` (DB-backed, `LoginAttempt`): login is limited per email only (`login/route.ts:70-74`, 5/min), Redis-only, silently disabled without Redis (`lib/cache/rate-limit.ts:59-68`) and fails open (`lib/api/rate-limit.ts:123`); `lib/auth/rateLimit.ts` does not exist; the `LoginAttempt` model is only seeded (`scripts/lib/seed-full-demo.ts:983`); the `standard` limiter keys on a client-supplied `x-user-id` that nothing sets; `POST /api/ai/insights` (paid LLM) has no limiter.
7. **RLS and tenant isolation overstated.** `DEPLOYMENT.md:233` ("RLS enforcement is not in question") and `:249` ("trusting tenant isolation"): RLS exists on `Product` only with a `businessId IS NULL` bypass; `forTenant()` is called by no route or page; `ci.yml:63` runs against a superuser that bypasses RLS (documented); `migrate deploy` never applies the RLS file.
8. **Env validation claims.** `README.md:332` ("Validated in lib/env.ts"), `:336` ("app will not start without these"), `:295`, `.env.example:2`: `validateEnv()` is never called (`DEPLOYMENT.md:84-88` and `ci.yml` say so, contradicting README); `JWT_SECRET` is enforced only in production (`jwt.ts:22-31`); the `.env.example` placeholder secret (line 25) is accepted as-is.
9. **LICENSE contradiction** (re-verified). `LICENSE` is MIT, "Copyright (c) 2026 Arnob Mahmud" (the upstream author); `README.md:3` has an MIT badge; `SECURITY.md:3` calls the repo "a commercial inventory management codebase"; `scripts/export-tier.ts` ships `LICENSE`, `README.md`, `SECURITY.md`, `docs/` and `scripts/` in every sold tier. Legal position: a decision for the owner, not for this scan. **Resolved 2026-10-21:** the owner chose "commercial"; `LICENSE` is now a proprietary commercial licence, the upstream MIT text is kept in `NOTICE`, both ship in exports (`docs/adr/0007-*`, ISS-0069). Still open: the legal entity and the real terms need review.
10. **MongoDB leftovers.** (Update 2026-10-21: `CLAUDE.md` lines 5 and 79 are corrected; line 76 is a note about legacy rows and stays.) `CLAUDE.md:5,76,79`, `PROJECT_WALKTHROUGH.md:31,50` (known), plus `README.md:537` ("audit-related collections") and code comments (`scripts/reset-demo-db.ts:4`, `lib/auth/demo-seed-users.ts:20,24`, `lib/products/product-query.ts` says there are no legacy rows).
