## High

**B1. `migrate-production.yml:53-57` pre-flight can never pass when there is something to migrate.** `prisma migrate status` has no `continue-on-error`; the installed CLI (`node_modules/prisma/build/index.js` ~L4020-4040) exits 1 when migrations are pending and when the database is not managed by Prisma Migrate (a brand-new production database). The `migrate deploy` step at line 59 is then skipped and the job fails. Fix: `continue-on-error: true` (or `|| true`) on the pre-flight; keep the post-flight.

**B2. CI test job is red and not a usable gate.** (Re-verified: the date failure, locally.) `ci.yml:145` runs `pnpm test`. `invoice-event-date.test.ts:35-41` hard-codes `dueDate: "2026-08-14"` and the code compares against the real clock, so it fails deterministically since 14 Aug; DEPLOYMENT.md calls it "flaky"; no test uses fake timers. `lib/server/tenant-prisma.test.ts` fails because the `postgres` service role is a superuser and bypasses RLS (documented in DEPLOYMENT.md §5/§7). The wipe-and-seed machinery in `ci.yml:114-145` serves only that one live-database test: 20 test files checked, including `prisma/invoice-client-access.test.ts`, all mock `@/prisma/client`, so the "20+ tests need seeded rows" comment is wrong. Fix: `vi.setSystemTime` or relative dates; in CI migrate and seed as owner, then test as a `NOSUPERUSER NOBYPASSRLS` role.

**B3. CI never runs lint or any tier-export check.** (Re-verified: no `lint` or `export:` step in any workflow.) The quality job (`ci.yml:25-64`) runs typecheck, `check:manifest` and build. DEPLOYMENT.md admits lint fails (8 errors, about 210 warnings); `eslint.tier-boundaries.mjs` is "warn" with about 266 known violations; `check:manifest` checks classification only. The tier boundary, the product's packaging guarantee, can break unnoticed. Fix: a matrix job that runs `pnpm export:$t "$RUNNER_TEMP/$t"` then `pnpm install --frozen-lockfile && pnpm typecheck && pnpm test` in the output; fix the 8 lint errors and gate on them.

**B4. RLS is applied by no deploy workflow.** (Re-verified: no migration contains RLS statements; only `ci.yml` applies `prisma/rls/*.sql`.) The file is non-idempotent (`CREATE POLICY` with no `DROP POLICY IF EXISTS`, line 14), covers only `"Product"`, and has the `OR "businessId" IS NULL` bridge. Tenant isolation on the future production database depends on one manual `psql` run that nothing verifies. Fix: make it idempotent, apply it in both migrate workflows, add a post-flight on `pg_class.relforcerowsecurity` and `pg_roles.rolbypassrls`; check the app role's `rolbypassrls` on Neon (the reviewer recalls console-created owner roles may have it, unverified).

**B5. `preview.yml:41,47,53` uses `secrets.VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` with no `environment:`.** DEPLOYMENT.md §5 says those secrets exist only in the `production` environment. Either preview fails on every PR to `main`, or a repo-level secret exists and anyone with push access can run `vercel deploy --prod` from a branch workflow and bypass the production environment gate. DEPLOYMENT.md also says PR previews come from Vercel's Git integration, so this duplicates them. Fix: preview-only token or project, or delete the workflow.

**B6. Destructive scripts have no guard.** `prisma/seed.ts` and `scripts/lib/delete-all-db-data.ts` wipe whatever `DATABASE_URL` points at; `prisma.config.ts` wires the seed to `prisma db seed`; the local `.env` points at hosted Neon, which is also the staging database; the seed creates `test@admin.com` with the shared demo password and similar; every export ships these scripts. Fix: refuse unless the host is allowlisted or `ALLOW_DESTRUCTIVE=1`; refuse when `NODE_ENV=production`.

## Medium

**B7. Production has no logging path.** `next.config.ts:23-25` `removeConsole` strips every server `console.*` including `error` and `warn`; `lib/logger.ts:73-130` emits nothing to the console in production and sends to Sentry only, which is optional (DEPLOYMENT.md §2); `sentry.server.config.ts` `consoleLoggingIntegration(["warn","error"])` never sees the compiled-out calls. Without `SENTRY_DSN`, errors vanish from Vercel logs; `prisma/client.ts`'s connection-error `console.error` is stripped too. Fix: `removeConsole: { exclude: ["error","warn"] }` and a console fallback in the logger.
**B8. Workflow hardening is missing.** No `permissions:` block and no `timeout-minutes` in any of the six workflows; actions pinned by tag only (including third-party `pnpm/action-setup@v4` in jobs holding production secrets); `pnpm add -g vercel@latest` unpinned in `deploy-production.yml:50` and `preview.yml:38`; tokens interpolated into command lines (`--token=${{ secrets.VERCEL_TOKEN }}`) instead of `env:`; no Dependabot.
**B9. The production gate rests on settings the repository cannot show.** The `production` environment does not exist yet (first dispatch auto-creates it unprotected); no required reviewers mentioned; no concurrency group on migrate or deploy; deploy does not require CI success on the SHA; `${{ github.ref }}` is interpolated into `run:` at `migrate-production.yml:36` and `deploy-production.yml:35`; the post-flight step has `if: always()` (line 66) and runs with production secrets even when the gate failed, before checkout. Fix: create the environment with reviewers and a `prod`-only branch policy now; pass `github.ref` via `env:`; add concurrency.
**B10. `migration-check.yml:23-50` is weak and over-privileged.** Informational (`|| true`); diffs the staging database against `schema.prisma`, not against the migrations folder, so a schema change with no migration passes; runs PR-controlled code (postinstall, `prisma.config.ts`, an edited workflow file) under `environment: staging`, which DEPLOYMENT.md says is unrestricted. Fix: `migrate diff --from-migrations prisma/migrations --to-schema-datamodel prisma/schema --shadow-database-url <service container> --exit-code` with no environment and no secrets.
**B11. The pnpm overrides do nothing.** `package.json:119-123` uses a top-level `overrides` key but pnpm reads `pnpm.overrides`; the lockfile has no `overrides:` block and still resolves `glob@7.2.3`, `rimraf@2.7.1`, `minimatch@3.1.5`/`5.1.9`, deprecated `inflight` and `fstream` (via exceljs → archiver 5 / unzipper 0.10). Forcing `glob>=11` would break `archiver-utils` at runtime, so scope carefully or replace exceljs.
**B12. Unused or misplaced dependencies** (no imports found in the source tree): `jsonwebtoken` + types (`jose` is the only JWT library used), `next-auth` 5 beta (pulls `@auth/core`, `preact`, `jose@5`), `js-cookie` + types, `cookies` + types, `autoprefixer` (`postcss.config.mjs` has only `tailwindcss`), `@types/exceljs@0.5.3` and `@types/bcryptjs@2` (both ship their own types). `@types/papaparse`, `@types/qrcode` belong in devDependencies. `lib/cache/redis.ts:8-9` statically imports both `ioredis` and `@upstash/redis`, so both are bundled.
**B13. Node, pnpm and Prisma setup is loose.** No `engines` or `packageManager`, but `prisma.config.ts` needs Node 20.12+ (`process.loadEnvFile`) and CI pins pnpm `10`; `package.json:7` `postinstall: npx prisma generate` would download whatever Prisma is latest if devDependencies are pruned; `build` repeats the generate.
**B14. `scripts/export-tier.ts:29,182` deletes an arbitrary output path.** `outDir` comes from argv and `fs.rmSync(outDir, {recursive, force})` has no guard: `pnpm export:core .` or `..` wipes the repo or its parent. Fix: refuse if `outDir` is `ROOT`, an ancestor, or a non-empty directory without a marker file.
**B15. Exports ship things they should not.** Verified in `../octalve-ims-core` (an older export from Sep 4): `docs/` copied whole (`export-tier.ts:104-105`), including `docs/local-dev-setup.md:13` (a local database password) and docs naming the sibling product Proplity; `scripts/` and `README.md` too; `eslint.config.mjs` imports `./eslint.tier-boundaries.mjs`, which `INTERNAL_ONLY` excludes, so `pnpm lint` in an export fails with module-not-found; `package.json` still lists `export:*` and `check:manifest` scripts whose files are removed; `vercel.json` ships `git.deploymentEnabled.prod=false`; `ALWAYS_EXCLUDE` matches exact root-relative paths only (a nested `.env*`, `node_modules` or `.DS_Store` would be copied; the root `.env` is safe because the copy is whitelist-based). **Partly fixed 2026-10-21:** the new internal docs (`docs/adr`, `docs/issues`, `docs/tasks`, `docs/development-history`, `docs/HANDOVER.md`, `docs/open-items.md`) are now in `ALWAYS_EXCLUDE`; the older docs still ship. Fix: an explicit docs allowlist and a per-tier `package.json`, eslint config and `vercel.json`.
**B16. `lib/react-query/invalidate-coverage.test.ts` breaks in Core and Pro exports.** In the shared bucket but hard-codes 19 pro/premium paths read via `readRepoFile` (lines 357-360): `app/api/shipping/labels/route.ts`, `app/api/payments/webhook/route.ts`, …; `pnpm test` in a customer export hits ENOENT.
**B17. Security headers are thin and hand-duplicated.** No CSP and no HSTS in code (Vercel adds HSTS on its domains, unverified); `X-XSS-Protection: 1; mode=block` is deprecated (OWASP: `0`); the same five headers live in `vercel.json:13-21` and `lib/vercel/production-headers.ts:13-19` with no sync test; `Permissions-Policy` covers camera and geolocation only; the `/_next/static` Cache-Control rule is redundant. No `dangerouslySetInnerHTML`, so CSP is defence in depth. Fix: report-only CSP allowing `js.stripe.com`, explicit HSTS, a unit test asserting `vercel.json` equals the constant.
**B18. `proxy.ts:57-60` redirects `/robots.txt` for anonymous users.** The matcher does not exempt it, so crawlers get a 307 to `/login` and `app/robots.ts` (the bot guardrail from `docs/VERCEL_PRODUCTION_GUARDRAILS.md`) never reaches them; the `(?!api|…)` lookahead is prefix-based, so `/api-docs` and `/api-status` bypass the proxy (those pages do their own auth). Static reasoning only.
**B19. Image and function limits are broader than needed.** `next.config.ts:9-23`: `ik.imagekit.io` has no `pathname`, so any ImageKit account's images consume your Image Optimization quota; `robohash.org` and `**.googleusercontent.com` are open too. `vercel.json:8-10` sets `maxDuration: 60` on every API route including health and the Sentry tunnel. DEPLOYMENT.md §3 says `vercel.json` "pins the region"; it does not.
**B20. Live-database test behaviour.** `lib/server/tenant-prisma.test.ts:14` uses `describe.skipIf(!process.env.DATABASE_URL)`, which checks only that the variable is set, not that the database is reachable (the header claims "unreachable"); `prisma/client.ts` connects eagerly at import; by DEPLOYMENT.md's account the test has passed on Neon staging, so a local run writes rows to the hosted database. Fix: require an explicit `RLS_TEST_DATABASE_URL`.
