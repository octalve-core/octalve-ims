# Scan 2026-10-21 — authentication, sessions, authorization primitives, tenancy

Method: static read of `lib/auth/*`, `lib/auth-server.ts`, `utils/auth*.ts`, `utils/axiosInstance.ts`, `proxy.ts`, `app/api/auth/**`, `app/api/users/**`, `app/api/user/**`, the refresh hooks, `lib/server/tenant-prisma.ts`, `prisma/rls/*.sql`. Nothing was run. The findings come from a delegated reviewer (model output); items marked **re-verified** were re-read by the main session on 2026-10-21. Everything else is "Read" evidence only. Register rows: `README.md`; this file holds the scenarios and fix directions.

## Critical

**A1. Anyone can self-register as a global admin; admin user management is not scoped.** (Re-verified: `role: "admin"` in `register/route.ts`.)
- `app/api/auth/register/route.ts:82` and `app/api/auth/oauth/google/callback/route.ts:51` create every account as `admin` (the code comment calls it a product decision). `app/api/users/route.ts:53-62` and `prisma/user-admin.ts:20-26` list every user; `app/api/users/[id]/route.ts:85-112, 150-169` let any admin change any user's role or name and hard-delete any user. `businessId` is never written.
- Scenario: a visitor registers, `GET /api/users` dumps every email, then `PUT role=client` on or `DELETE` another customer's admin.
- Fix direction: first-user-only or invite-only admin creation; default new accounts to a least-privilege role; scope user management and every admin query by business or owner.

## High

**A2. Unauthenticated email relay.** (Re-verified: no session check in `POST /api/notifications`; it returns 503 only when Brevo is unconfigured.) `app/api/notifications/route.ts:33`: `recipientEmail`, `adminEmail`, `data` come from the body; `lib/email` does no HTML escaping. GET (`:171`) leaks the admin email. Fix: require a session and role; rate-limit.

**A3. `Bearer undefined` bypass on `/api/invoices/reminders`.** (Re-verified.) `app/api/invoices/reminders/route.ts:33-42` compares to `` `Bearer ${process.env.INTERNAL_API_KEY}` ``; with the variable unset (commented out in `.env.example`), `Authorization: Bearer undefined` passes. It then emails every client with a due invoice and flips statuses for all tenants. Fix: reject when the variable is falsy; `timingSafeEqual`.

**A4. Other routes with no or conditional authentication.** `email/queue/process/route.ts:26` skips signature verification when QStash env is unset (arbitrary email job); `shipping/webhook/route.ts:18-70` has no signature check (re-verified); `product-reviews/by-product/[productId]/route.ts` is public (returns `reviewerEmail`, `userId`; `?status=all|pending` returns unmoderated reviews); `performance/route.ts:34` and `system-metrics/route.ts:19` are open. Fix: authenticate or verify signatures, and fail closed when the secret is missing.

**A5. Google OAuth account takeover.** (Re-verified: no `verified_email` check.) The callback (`:214-244`) finds the user by email only, links `googleId` (`:91-93`) and logs in; registration does no email verification. Scenario A: an attacker registers `victim@gmail.com` with their own password; the victim later uses Google and lands in the same account, and the attacker's password still works. Scenario B (needs runtime check): a Google account with an unverified address. Fix: require `verified_email === true`; verify email at registration; do not auto-link to a password account without proof.

## Medium

**A6. Rate limits fail open and are non-atomic.** `lib/cache/rate-limit.ts:58-68, 110-117` allow everything when Redis is absent or errors; `redis.ts:337-340` ignores `REDIS_URL` on Vercel; without Upstash vars, login/register/forgot/reset are unthrottled; the sorted-set calls (`:77-102`) are separate, so a parallel burst passes. Fix: atomic script or INCR+EXPIRE; fail closed on auth presets.

**A7. Rate-limit keying.** Login is keyed per email only (`login/route.ts:70-75`): password spraying across emails is free, and anyone can lock out a victim with 5 requests a minute. Register, refresh and reset-password share one `ip:<ip>` bucket at 5/min (`lib/api/rate-limit.ts:61-67`; both IP headers absent means a global `ip:unknown`); behind a NAT, refreshes alone can hit 429 and the client treats that as a logout. Forgot-password is per email only. `verify-email` and `change-password` have no limit (unlimited current-password guesses with a stolen session). The `standard` and `strict` presets trust a client-sent `x-user-id` header (`rate-limit.ts:41, 53`).

**A8. Refresh race logs the user out everywhere.** `refresh/route.ts:56-74`: a concurrent loser sees a revoked row, revokes the whole family and clears cookies, possibly overwriting the winner's new cookies. `hooks/use-auth-refresh.ts:25` uses raw `fetch`, not the single-flight `refreshAccessToken()`, and its `/auth/session` re-check fails because the access cookie was just deleted. Fix: grace window for the just-rotated token; do not clear cookies on the loser path; route the timer through the shared single-flight. (Needs runtime check; also reported independently by the frontend reviewer.)

**A9. Refresh slides forever and ignores the session's original lifetime.** `refresh/route.ts:99, 115` always use `REFRESH_DAYS.default` (7 days). "Keep me signed in" off (1 day) becomes 7 at first refresh; 30 becomes 7; a stolen rotating token never expires. Fix: carry the family's expiry through rotation; cap absolute age.

**A10. A wrong-password 401 on login triggers the refresh interceptor and a hard redirect.** `utils/axiosInstance.ts:33-51`, `lib/api/client.ts:123-141` exempt only `/auth/refresh`. The failed refresh then sets `window.location.href="/"`: the error toast is lost and each failure burns the shared refresh bucket (A7). Fix: exempt `/auth/*`. (The walkthrough step S-003 will show it.)

**A11. CSRF on 6 routes only** (login, register, refresh, logout, forgot-password, change-password). About 33 cookie-authenticated POST/PUT/DELETE route files have none (users, system-config, products, orders, invoices, stock-transfers, payments/checkout, notifications, email-preferences, …); `SameSite=Lax` (`lib/auth/cookies.ts:47-60`) is the only protection. Fix: one shared Origin check for non-GET `/api` requests.

**A12. Reset link built from request headers** (`forgot-password/route.ts:85`, `request.nextUrl.origin`); `validateCSRF` trusts the same Host/X-Forwarded-Host. Not exploitable on Vercel (headers rewritten); exploitable behind a proxy that forwards them. Fix: fixed `APP_URL`. (Plausible, needs deployment check.)

**A13. User enumeration.** Register returns 409 "already exists" (`:54-58`); login skips bcrypt for unknown users (`login/route.ts:79-84`, timing); forgot-password does the upsert and the awaited Brevo send only for real accounts (`:55-105`) and logs the raw email (`:60`); register's catch returns `Registration failed: ${error.message}` (`:126-131`, Prisma internals). Fix: dummy bcrypt compare, generic responses, async mail.

**A14. Revocation gaps.** Logout (`logout/route.ts:34-44`) revokes refresh tokens only if the access JWT is still valid; access JWTs have no `jti`/version, so they work 15 minutes after logout or password change; `verify-email` password set does not revoke sessions (and nothing creates verification tokens, so the route is dead).

**A15. Demo credentials ship ungated.** `lib/auth/demo-seed-users.ts:15` (shared password), `components/Pages/LoginPage.tsx:16, 115, 194` pre-fill them with no env gate; `README.md:312` lists them. If `test@admin.com` was seeded into the hosted database it is a public admin login. (Code confirmed; whether the account exists on a deployed database is unknown.)

**A16. RLS and `tenant-prisma` are effectively a no-op.** Policy on `Product` only; `businessId IS NULL` rows visible to everyone and every row is NULL; `forTenant` has no caller outside its test (re-verified); its per-operation batch transaction (`tenant-prisma.ts:33`) does not compose with interactive transactions; if the Neon app role has `BYPASSRLS` even `FORCE` RLS is skipped (check `select rolbypassrls from pg_roles`). See ADR 0005.

## Low

- **A17.** OAuth state uses `Math.random` (`oauth/google/route.ts:25-28`); the `callback` param is stored but never read, so no open redirect; Google-created users get a `Math.random`-based password (`callback/route.ts:35`).
- **A18.** `can()` (`lib/auth/can.ts`): null role becomes "user" with write grants (`:80`); the `roleId` path ignores `role`, so a demoted user with a `roleId` keeps permissions; last-admin demote/delete is not prevented (dormant: nothing writes `roleId`).
- **A19.** `jwt.ts:21-27` throws in production without `JWT_SECRET` (correct) but has no length/placeholder check; `validateEnv()` is never called; the dev fallback secret is public if `NODE_ENV` is not "production". The local `.env` secret is not the placeholder (47 characters).
- **A20.** TanStack cache (`lib/react-query/persister.ts:30-34`) and a `getSession` blob sit in localStorage in plaintext; cleared on logout and null session. Minimum password length is 6 everywhere.

## What held up

Refresh rotation uses one atomic `updateMany` (single use holds; family revocation on reuse works); reset tokens are random, sha256-hashed, 60 minutes, single use, with a transactional delete, and a reset revokes all refresh tokens; register ignores `role`/`roleId`/`businessId` from the body (zod strips unknown keys); admin user routes check the role against the database row, not the JWT claim; cookie flags are sound (httpOnly, Lax, secure in production, refresh cookie path-scoped); the `proxy.ts` matcher gaps are not exploitable because each page calls `getSession`; no functional `session_id` leftovers.

## Not covered

Per-resource ownership in the ~70 non-auth routes (see the API review); live Neon role privileges; Vercel environment variables.
